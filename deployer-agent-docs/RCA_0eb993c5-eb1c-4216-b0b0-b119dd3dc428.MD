# RCA — Hub Trade: Admin Control sees no clients from /api/integration/*

## Problem statement
Second app (Admin Control 241) pulls from Hub Trade's API-key-protected endpoints
`GET /api/integration/clients` and `GET /api/integration/tickets` (header `X-API-Key`,
validated against backend env `INTEGRATION_API_KEY`). No clients appeared in Admin Control.
Requested: verify (1) secret exists/non-empty, (2) deployed build has the routes, (3) recent
backend errors mentioning /api/integration. Read-only, no deploy.

## Scope
Active run: `0eb993c5-eb1c-4216-b0b0-b119dd3dc428` (success, serving traffic).
Deployment: trade-hub-910, frontend_type=cloudflare. Live URL https://trade-hub-910.emergent.host
(custom domains trademainhub.com / www verified).

## Findings (all three checks PASS on the production side)

1. **Secret INTEGRATION_API_KEY — PRESENT and NON-EMPTY.**
   `list_secrets` on the active run lists `INTEGRATION_API_KEY` with `is_empty:false`
   (metadata_available:true). The key exists in the production secret store and holds a value.
   NOTE: the actual value is never returned — I confirmed it is set, NOT that it equals the
   value Admin Control sends.

2. **Deployed build INCLUDES the /api/integration/* routes.**
   `GET https://trade-hub-910.emergent.host/api/integration/clients` with no key returned
   **HTTP 401, body `{"detail":"Invalid API key"}`**. This is the "routes exist, key rejected"
   response — not a 404. So the currently deployed image contains the integration router and its
   X-API-Key auth guard.

3. **No recent backend errors mentioning /api/integration.**
   `fetch_app_logs` (run 0eb993c5, filter "integration", last 1440 min) returned 0 matching
   lines. No 5xx, traceback, or auth-related crash tied to these routes.

## Root cause (so far)
The Hub Trade production side is healthy: the secret is set, the routes are deployed, and the
endpoints respond correctly (401 to an unauthenticated request). The failure is therefore NOT in
this deployment. The most likely cause is on the consumer side — Admin Control 241 is either not
sending the `X-API-Key` header, or is sending a value that does not match Hub Trade's
`INTEGRATION_API_KEY` (a 401 "Invalid API key" is exactly what a key mismatch produces, and that
same 401 would surface in Admin Control as "no clients"). This cannot be fully confirmed from the
Hub Trade side because the stored secret value is not readable and Admin Control's request/logs
are a separate deployment.

## Suggested next steps
- Verify the API key value configured in Admin Control 241 exactly matches Hub Trade's
  `INTEGRATION_API_KEY` (Deployment Panel → Secrets). A trailing space / stale value is the usual
  culprit.
- Confirm Admin Control sends the header name `X-API-Key` (exact casing) to
  `https://trademainhub.com/api/integration/clients`.
- If values are confirmed equal and it still 401s, capture the outbound request from Admin Control
  (header actually sent) to see what the backend receives.
